# Gather 운영자 가이드

어떤 교회든 자기만의 독립된 공지·채팅 앱을 만들어 쓸 수 있는 플랫폼입니다. 앱 화면은 모두 영어이고, 이 가이드는 운영자(목사님)용입니다.

> `index.html`을 그냥 열면 **미리보기 모드**(가짜 데이터)로 보여요. 아래 1~8단계를 한 번만 하면 실제 서비스가 됩니다.

---

## 어떻게 동작하나요

- **교회(그룹)마다 완전히 분리돼요.** 각 그룹은 서로의 존재조차 알 수 없어요. 그룹 목록을 보는 기능 자체가 없고, 초대 코드를 받은 사람만 그 그룹의 이름·로고를 볼 수 있어요.
- **메시지·사진·파일·공지·그룹방 이름·신고 내용은 폰에서 암호화(종단간 암호화)**된 뒤 서버로 가요. 서버에는 알아볼 수 없는 데이터만 저장돼요. 운영자인 목사님도, 그 교회 리더도 못 읽어요.
- 각 사람은 처음 가입할 때 **복구 비밀번호**를 정해요. 새 폰에서 로그인할 때 이걸로 예전 메시지를 다시 열어요.
- 새 사람이 승인되면, 이미 있는 사람들의 앱이 열쇠를 자동으로 나눠 줘요.

### 각 그룹 리더가 할 수 있는 것 (Manage 탭)
- **People**: 가입 요청 승인/거절, 리더 지정, 내보내기
- **Reports**: 아이들이 신고한 메시지 확인 → "Remove" 또는 "Mark as handled"
- **Invite**: 초대 링크·코드 복사, 새 링크 만들기(예전 링크는 바로 막힘)
- **Customize**: 앱 이름, 한 줄 소개, 색깔, 로고, 환영 메시지 → 그 그룹 사람들에게만 적용

### 신고 버튼
메시지를 탭하면 **Report**가 나와요. 이유를 고르면 그 메시지 하나만 그 그룹 리더들에게 암호화돼서 전달돼요. 신고당한 사람에겐 누가 신고했는지 알려지지 않아요. 리더는 신고로 받은 메시지만 볼 수 있고, 비공개 대화방은 여전히 못 봐요.

---

## 운영자가 볼 수 있는 것 / 없는 것 (정직하게)

| Firebase 콘솔에서 **볼 수 있는 것** | **볼 수 없는 것** |
|---|---|
| 가입자 이름, 이메일, 프로필 사진 | 메시지 내용 |
| 어떤 그룹이 있는지, 그룹 이름·로고 | 사진, 파일 내용 |
| 누가 어느 그룹·어느 대화방에 있는지 | 공지 내용 |
| 메시지를 보낸 시각, 파일 크기 | 그룹방 이름, 신고 내용 |

**알아두실 한계**
1. **앱 코드는 운영자가 올려요.** 운영자가 나중에 몰래 코드를 바꿔 비밀번호나 키를 빼돌리게 만드는 것은 기술적으로 가능해요. 이걸 막는 표준 방법은 **코드를 GitHub에 공개**해서 누구나 확인할 수 있게 하는 거예요. 교회들이 원하면 직접 코드를 받아 자기 사이트에 올려 쓸 수도 있어요.
2. **복구 비밀번호가 너무 쉬우면** 서버 데이터를 가진 사람이 오랜 시간 추측해서 풀 수도 있어요. 앱이 일부러 느리게 만들어 두었지만, 아이들에게 "짧은 문장"을 쓰라고 안내해 주세요.
3. **내보낸 사람**은 보안 규칙으로 즉시 막히지만, 그 사람이 이미 받아 둔 열쇠까지 바꾸지는 않아요. (데이터 자체를 못 가져가니 실제 위험은 작아요.)
4. 비밀번호를 잊으면 "Start fresh"로 새로 시작할 수 있어요. 다른 사람이 함께 있는 방은 자동으로 다시 열리고, **혼자만 남은 방은 복구할 수 없어요.**
5. 아직 **푸시 알림은 없어요.** 앱을 열면 탭과 방 목록에 새 글 표시가 나와요.

---

## 법적 책임 (꼭 읽어 주세요)

여러 교회가 쓰는 서비스를 운영하면 목사님이 **운영자**가 돼요.
- 미국에서는 **만 13세 미만** 아이의 개인정보(이름·이메일·사진)를 모으려면 **COPPA**에 따라 **부모의 확인 가능한 동의**가 필요해요. 가장 간단한 방법은 13세 이상만 쓰도록 하거나, 각 교회가 부모 동의를 받고 리더가 승인하는 방식이에요.
- **개인정보처리방침(Privacy Policy)과 이용약관**을 사이트에 올리셔야 해요. 원하시면 초안을 만들어 드릴게요. 실제 적용 전에는 변호사 확인을 권해요.
- 13세 미만 구글 계정(Family Link)은 부모 허락 없이 외부 앱 로그인이 막힐 수 있어요.

## 운영자 1회 설정 (약 30분)

### 1. Firebase 프로젝트
1. https://console.firebase.google.com → **프로젝트 추가** → 이름 예: `gather-app`
2. 요금제는 **Spark(무료)** 그대로 두면 돼요. 카드 등록이 필요 없어요.
   - 사진·파일은 암호화된 채로 데이터베이스에 나눠 저장해서, 별도 저장소(유료)를 쓰지 않아요.
   - 무료 한도: 데이터베이스 1GB, 하루 읽기 5만 번·쓰기 2만 번. 교회가 많아져 한도에 가까워지면 그때 Blaze로 바꾸면 돼요.

### 2. 웹 앱 등록 → 설정값 넣기
1. 프로젝트 홈에서 **`</>`** → 앱 닉네임 `Gather` → 등록
2. 나오는 `firebaseConfig` 값을 `index.html`의 `const firebaseConfig = {` 부분에 붙여넣기
3. **`authDomain`만** Netlify 주소로 바꾸기 → 예: `"gather-app.netlify.app"`
4. 플랫폼 이름을 바꾸고 싶으면 바로 아래 `const APP_NAME = "Gather";` 를 수정

### 3. 구글 로그인 켜기
1. **빌드 > Authentication** → 시작하기 → **로그인 방법** → **Google** 사용 설정 → 저장
2. **설정 > 승인된 도메인**에 Netlify 주소(`gather-app.netlify.app`) 추가

### 4. Firestore 데이터베이스
1. **빌드 > Firestore Database** → 만들기 → 위치 `us-east4` → **프로덕션 모드**
2. **규칙** 탭 → 내용을 지우고 `firestore.rules` 전체를 붙여넣기 → **게시**
3. 처음 앱을 쓸 때 "색인(index)이 필요하다"는 오류가 콘솔에 뜨면, 오류 메시지 안의 링크를 눌러 만들면 돼요 (보통 필요 없음).

### 5. 로그인 마무리 (아이폰 홈 화면 앱용)
1. `netlify.toml`의 `YOUR_PROJECT` 두 곳을 Firebase **프로젝트 ID**로 바꾸기
2. https://console.cloud.google.com/apis/credentials → `Web client (auto created by Google Service)` →
   **승인된 리디렉션 URI**에 `https://gather-app.netlify.app/__/auth/handler` 추가 → 저장

### 6. Netlify에 올리기
- 새 사이트 → 이 폴더 전체 업로드 (또는 GitHub 연결 — 코드 공개용으로도 추천)
- 사이트 이름을 정하면 2·3·5단계 주소와 똑같이 맞춰 주세요

## 교회가 시작하는 방법 (각 교회 리더에게 보낼 안내)

1. 사이트 주소 열기 → **Continue with Google**
2. **복구 비밀번호** 정하기 (꼭 적어 두기)
3. **Start a new group** → 그룹 이름 입력 → 첫 리더가 됨
4. **Manage > Invite**에서 링크 복사 → 아이들·부모님께 보내기
5. 아이들이 링크로 들어와 가입 요청 → **Manage > People**에서 **Approve**
6. **Manage > Customize**에서 이름·색깔·로고·환영 메시지 꾸미기

FGYG도 이 방법으로 첫 그룹을 만들면 돼요.

아이들 안내:
- 아이폰: **Safari**로 링크 열기 → 공유 → **홈 화면에 추가**
- 안드로이드: Chrome → 메뉴 ⋮ → **앱 설치**

---

## 앱 다운로드(설치) 페이지

`download.html`이 설치 페이지예요. 사이트에 올리면 주소는 `https://gather-app.netlify.app/download.html` 이 돼요.

- **아이폰**: Safari에서 "홈 화면에 추가" 3단계를 그림과 함께 보여 줘요. 카카오톡·인스타그램 안에서 열면 "Safari로 열기" 안내가 먼저 나와요.
- **안드로이드**: **Install app** 버튼 한 번으로 설치돼요. 버튼이 안 되는 폰(삼성 인터넷 등)은 메뉴로 설치하는 방법이 바로 나와요. 카카오톡 안에서 열면 "Chrome으로 열기" 버튼이 나와요.
- **컴퓨터**: 폰으로 찍을 수 있는 QR 코드가 떠요.
- 리더가 **Manage > Invite**에서 복사하는 초대 링크는 이제 이 설치 페이지로 연결되고, 페이지에 **초대 코드**가 크게 표시돼요. 아이들은 앱을 설치한 뒤 첫 화면의 "Have an invite code?"에 그 코드를 넣으면 돼요.
  (아이폰은 Safari와 홈 화면 앱이 저장 공간을 따로 써서, 링크만으로는 코드가 앱에 넘어가지 않아요. 그래서 코드를 직접 넣는 방식이에요.)

교회 주보, 단톡방, QR 포스터에는 설치 페이지 주소를 쓰시면 돼요. 업데이트는 사이트에 새 파일을 올리면 모든 사람에게 자동으로 적용돼요.

## 실제로 올린 뒤 꼭 해 볼 보안 테스트

이 작업 환경에서는 Firebase 테스트 도구를 설치할 수 없어서, 보안 규칙을 자동 테스트로 돌려 보지 못했어요. 대신 직접 줄마다 검토했고, 올린 뒤 아래를 확인해 주세요. 구글 계정 3개(A, B, C)로 하면 돼요.

| # | 해 볼 것 | 기대 결과 |
|---|---|---|
| 1 | A가 그룹 1 만들기, B가 그룹 2 만들기 | 서로의 그룹이 어디에도 안 보임 |
| 2 | C가 그룹 1 초대 링크로 가입 요청 | 승인 전엔 공지·채팅이 안 보임 |
| 3 | A가 C 승인 | C에게 공지와 전체 채팅이 보임 (잠깐 "Waiting for access"였다가 풀림) |
| 4 | C가 A 말고 다른 사람과 1:1 채팅 | A(리더)의 Chats 목록에 그 방이 없음 |
| 5 | Firebase 콘솔 > Firestore에서 메시지 문서 열기 | `ct`에 알아볼 수 없는 글자만 있음 |
| 6 | Firestore의 `files/…/parts` 문서 열기 | 알아볼 수 없는 글자만 있음 (암호화됨) |
| 7 | C가 메시지 신고 | A의 Manage > Reports에 나타남 |
| 8 | A가 C 내보내기 | C의 화면이 "Access removed"로 바뀜 |
| 9 | C가 다른 브라우저에서 로그인 | 복구 비밀번호를 물어보고, 맞으면 예전 메시지가 보임 |

Firebase 콘솔의 **Firestore > 규칙 > 규칙 플레이그라운드**에서도 "다른 그룹 문서 읽기"가 거부되는지 시험해 볼 수 있어요.
